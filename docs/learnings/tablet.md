# Learnings: iPad and other tablets

- **Emulate an iPad honestly.** iPadOS Safari says it is a Mac: its user agent says Macintosh, `navigator.platform` is `MacIntel`, and `maxTouchPoints` is 5. Emulation in Playwright needs `hasTouch`, `isMobile` and an init script that sets `platform` and `maxTouchPoints`. Without them, shortcut labels say Ctrl and the app looks like it runs on Linux. iPad Safari also has no `getDisplayMedia`, so delete it in the init script to see what Clips does.
- **768 to 1099 px is its own layout.** That range is an upright iPad: wider than the phone layout (`MOBILE_QUERY`) but too narrow for a page and a 320–380 px side panel next to each other. In that range, panels marked `side-pane` float over the page (`app.css`). `PANES_QUERY` (≥ 1100 px) is the same breakpoint in JS, for choices like whether a meeting opens with its transcript.
- **A floating pane has to know what sits above the top bar.** The recording strip adds 2.25 rem on other pages while a meeting is live (`main[data-strip]`). A component that is used both as a panel and inside a card (the live transcript in Voice notes) opts in with a prop. A global class would move it in both places.
- **Unlayered CSS beats Tailwind.** Tailwind v4 utilities live in `@layer utilities`, so any unlayered rule wins over them, whatever the specificity. Helper rules that utilities must still be able to override (`.tap-target`) go in `@layer components`. A `position: relative` there once pushed an `absolute` button out of its sidebar, on touch screens only.
- **A tap test doesn't prove the button is on screen.** Playwright scrolls an element into view before it taps. Assert `toBeInViewport()` and the position first, and check `matchMedia('(pointer: coarse)')` so the test really runs the touch CSS.
- **Pick top-bar buttons by test id.** File tree rows have "Actions for <name>" buttons, and a role query for "Share" matches those too once a test has made a file with "share" in its name.
- **Some things only a real iPad shows:** Safari zooms on inputs under 16 px, ⌘ keys Safari keeps for itself, and how the Tab key moves between fields. Hand those to Morgan as steps.
